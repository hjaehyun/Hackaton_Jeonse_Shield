# 전세방패 — 실거래가 연동 설계서

작성일: 2026-09-21
대상 범위: 목업 데이터를 국토교통부 실거래가 API 실데이터로 교체하는 작업
현재 상태: 화면 3개와 계산 로직은 완성, 데이터만 고정 목업

---

## 1. 무엇을 만드는가

이용자가 **지역 · 단지 · 전용면적 · 보증금**을 입력하면,
같은 단지의 **실제 매매 거래**를 조회해 전세가율을 계산하고 위험 구간을 판정한다.

지금은 `public/app.js`의 `mockTrades` 배열 14건을 쓴다. 이것을 실데이터로 바꾼다.

### 범위에 들어가는 것

- 실거래가 API를 호출하는 Worker 프록시 라우트
- XML → JSON 변환과 정규화 (이미 `src/lib/rtms.js`에 구현·테스트 완료)
- D1 기반 응답 캐시
- 단지명 후보 선택 UI (자동 매칭 대신 이용자가 고른다)
- 표본이 없을 때의 정직한 실패 화면

### 범위에 들어가지 않는 것

- 법령·판례 API 연동 (별도 작업, 자리표시자 유지)
- LLM 요약
- 연립다세대·단독다가구
- 로그인, 결과 저장, 지도

## 2. 제약

설계를 지배하는 것은 런타임 제약이다.

| 제약 | 값 | 출처 |
|---|---|---|
| CPU | 요청당 10ms (무료 플랜) | Cloudflare Workers |
| 서브리퀘스트 | 요청당 50개 | Cloudflare Workers |
| 바인딩 | **D1, R2만.** KV 금지 | Genspark 호스팅 배포 검증 |
| API 쿼터 | 일 10,000건 (개발계정) | 공공데이터포털 |
| API 응답 | XML 전용 | 국토교통부 |
| 마감 | 2026-09-27 22:00 | 해커톤 |

**CPU 10ms가 실질적 설계 제약이다.** 네트워크 대기는 계산에 들어가지 않지만 파싱은 들어간다.
그래서 범용 XML 파서를 쓰지 않고, `numOfRows`를 낮추고, 캐시로 파싱 자체를 건너뛴다.

## 3. 아키텍처

```
[브라우저]
   │  같은 오리진 — CORS 없음
   ▼
[Cloudflare Workers · Hono]
   │
   ├─▶ D1 (binding: DB)          cache 테이블, lawdCd+ym 단위
   │
   └─▶ apis.data.go.kr            serviceKey 는 서버에만 존재
         ├─ RTMSDataSvcAptRent    전월세
         └─ RTMSDataSvcAptTrade   매매
```

### 서버 프록시를 쓰는 이유

실측 결과 `apis.data.go.kr`는 200 응답에도 `Access-Control-Allow-Origin`에
요청 Origin을 에코한다. **CORS 때문이 아니다.**

브라우저에서 직접 호출하면 `serviceKey`가 개발자도구 네트워크 탭에 노출되고,
프론트엔드 번들에 들어간 값은 공개 GitHub 저장소에 그대로 올라간다.
키를 서버에 가두는 것이 프록시의 유일한 존재 이유다.

## 5. 설계상의 두 가지 어려움

### 5.1 매매 응답에 `aptSeq`가 없다

전월세에는 단지 고유 ID인 `aptSeq`가 있지만 매매에는 없다.
전세가율은 `보증금 ÷ 같은 단지 매매 중위가`이므로 두 데이터를 이어야 하는데,
이을 수 있는 키가 **단지명 문자열뿐**이다.

**대응:** `complexKey()` (구현·테스트 완료)

```
괄호 제거 · 공백 제거 · 소문자화, 숫자는 보존

광화문스페이스본(101동~105동)  →  광화문스페이스본
e편한세상 신촌 / E편한세상신촌   →  같은 키
아남아파트 3차 / 아남아파트 2차  →  다른 키
```

**받아들이는 손실:** 괄호 안 내용만 다른 두 단지는 한 키로 합쳐진다.
`aptSeq`가 없는 이상 "동 범위 표기"와 "진짜 다른 이름"을 구분할 방법이 없다.

**설계 결정 — 자동 매칭을 하지 않는다.**
이용자가 단지명을 자유 입력하면 오타·약칭·표기 차이로 매칭이 실패한다.
실패하면 "표본 부족"이 나오는데, 이용자는 그것이 *데이터가 없어서*인지
*이름을 잘못 써서*인지 알 수 없다.

그래서 **입력 대신 선택**으로 바꾼다. 시군구를 고르면 그 지역에 실제로 거래가 있는
단지 목록을 받아 이용자가 고른다. 고른 단지는 키가 확정되므로 매칭이 실패하지 않는다.

### 5.2 해제된 거래가 섞여 있다

`cdealType`이 비어 있지 않으면 국토교통부가 나중에 취소 처리한 거래다.
중위가는 전세가율의 분모이므로, 취소된 거래가 남아 있으면 판정이 통째로 틀어진다.

**대응:** `activeTrades()` (구현·테스트 완료)로 계산 전에 제거한다.

## 6. API 계약

모든 라우트는 같은 오리진이며 인증이 없다. 실패는 HTTP 상태와 `error` 코드로 표현한다.

### `GET /api/complexes`

지역과 기간에서 거래가 존재하는 단지 목록. 위저드 2단계가 쓴다.

```
쿼리   lawdCd=11110   (5자리 숫자, 필수)
       months=6       (1~12, 기본 6)

200    {
         "lawdCd": "11110",
         "months": 6,
         "complexes": [
           { "key": "광화문스페이스본", "name": "광화문스페이스본", "tradeCount": 12, "rentCount": 31 }
         ]
       }
```

- `name`은 가장 최근 거래에 나타난 표기를 쓴다.
- `tradeCount`가 0인 단지도 포함한다. 전세가율은 못 내지만 전월세 시세는 보여줄 수 있다.
- 정렬: `tradeCount + rentCount` 내림차순.

### `GET /api/complex`

한 단지의 거래 내역. 결과 화면이 쓴다.

```
쿼리   lawdCd=11110
       key=광화문스페이스본   (complexKey 결과, 필수)
       months=6

200    {
         "key": "광화문스페이스본",
         "name": "광화문스페이스본",
         "months": 6,
         "trades": [ { "area": 97.61, "price": 96000, "floor": 5, "year": 2026, "month": 6, "day": 27 } ],
         "rents":  [ { "area": 97.61, "deposit": 96000, "monthlyRent": 0, "floor": 1, "year": 2026, "month": 6, "day": 27 } ],
         "cancelledCount": 2
       }
```

- `trades`는 **이미 해제 거래가 제거된** 목록이다. `cancelledCount`는 몇 건을 걸렀는지 알린다.
- `name`은 표기가 여럿이면 가장 최근 거래의 것.

### 오류 응답

| 상태 | `error` | 뜻 | 화면 처리 |
|---|---|---|---|
| 400 | `INVALID_PARAMETERS` | 파라미터 형식 오류 | 입력 단계로 되돌림 |
| 502 | `UPSTREAM_UNAVAILABLE` | 공공데이터포털 응답 실패·타임아웃 | "조회 실패, 잠시 후 다시" |
| 503 | `KEY_NOT_CONFIGURED` | 서버에 키가 없음 | 동일 |

**오류 본문에 업스트림 URL이나 예외 메시지를 넣지 않는다.** 둘 다 `serviceKey`를 포함할 수 있다.

## 7. 캐시

### 왜 필요한가

1. CPU 10ms — 캐시 히트면 XML 파싱이 일어나지 않는다
2. 일 10,000건 쿼터 — 같은 지역·월을 반복 조회하지 않는다
3. 응답 속도 — 시연에서 체감 차이가 크다

한 번의 진단은 `months=6` 기준 **12회 업스트림 호출**(전월세 6 + 매매 6)이 필요하다.
캐시가 없으면 같은 지역을 두 번째 조회할 때도 12회를 다시 쓴다.

### 스키마

D1에는 TTL이 없다. 만료를 컬럼으로 직접 관리한다.

```sql
CREATE TABLE IF NOT EXISTS cache (
  k          TEXT PRIMARY KEY,
  v          TEXT NOT NULL,
  expires_at INTEGER NOT NULL
);
```

키는 `rent:<lawdCd>:<ym>` / `trade:<lawdCd>:<ym>` — **업스트림 호출 단위로 캐시한다.**
`/api/complexes`와 `/api/complex`는 같은 월별 캐시를 공유한다.

TTL 24시간. 실거래가는 신고 기준이라 그보다 자주 바뀌지 않는다.

### 동작 규칙

- 테이블은 Worker가 첫 요청에서 `CREATE TABLE IF NOT EXISTS`로 만든다.
  배포 경로에서 마이그레이션을 돌릴 수 없을 수 있기 때문이다.
  모듈 레벨 플래그로 아이솔레이트당 1회만 실행한다.
- 쓰기는 `c.executionCtx.waitUntil()`로 빼서 응답을 지연시키지 않는다.
- **D1 바인딩이 없어도 서비스는 동작해야 한다.** 캐시 계층은 없으면 통과한다.
- 만료된 행은 조회 조건에서 걸러진다. 별도 청소 작업을 두지 않는다.

## 8. 화면 변경

### 위저드 2단계: 자유 입력 → 후보 선택

```
현재   [텍스트 입력]  "예: 전세방패 아파트"
변경   [목록]         종로구에서 최근 6개월 거래가 있는 단지
                     검색어로 좁히기 가능
                     "찾는 단지가 없나요?" → 이유 안내
```

목록이 비면 그 지역·기간에 아파트 거래가 없다는 뜻이다. 그대로 말한다.

### 결과 화면

계산 로직(`ratio.js`)과 렌더링은 **그대로 둔다.** 입력 데이터만 바뀐다.

추가로 표시할 것:

- 조회 기간 (`2026.04 ~ 2026.09`)
- 해제 거래를 걸렀다면 그 건수
- 매매 표본이 3건 미만이면 전세가율을 내지 않고, **전월세 분포만** 보여준다

### 표본이 부족할 때

지금도 `verdict()`가 `표본 부족 — 판정 불가`를 반환한다. 이 동작을 유지하되,
**이유를 구분해서** 알린다.

| 상황 | 문구 |
|---|---|
| 매매 거래가 아예 없음 | "이 단지는 최근 6개월 매매 거래가 없어 전세가율을 계산할 수 없습니다" |
| 유사 면적 매매가 3건 미만 | "전용 84㎡ 부근 매매가 2건뿐이라 중위가를 신뢰할 수 없습니다" |
| 기간을 넓히면 될 수 있음 | "12개월로 넓혀 다시 조회" 버튼 |

**절대 하지 않는 것:** 표본을 늘리려고 면적 허용범위(±10%)를 임의로 넓히거나,
값을 보간하거나, 다른 단지 거래를 섞는 것.

## 9. 보안

| 항목 | 규칙 |
|---|---|
| `serviceKey` | Workers 시크릿에만 존재. 소스·`wrangler.jsonc`·프론트엔드 번들 금지 |

| 파라미터 | `lawdCd`는 `/^\d{5}$/`, `ym`은 `/^\d{4}(0[1-9]|1[0-2])$/`로 검증 후 사용 |

## 10. 정확성 원칙

이 서비스의 가장 큰 결함은 틀린 숫자를 자신 있게 보여주는 것이다.

1. **표본 3건 미만이면 비율을 표시하지 않는다.** 이미 구현되어 있다.
2. **해제 거래를 제외한다.**
3. **화면에 찍히는 모든 숫자는 관측값이다.** 패딩·보간·추정값을 표시하지 않는다.
   (차트 축 레이블이 이 원칙을 어겨 2026-09-21에 수정했고, 회귀 검사로 고정했다.)
4. **실거래가는 신고 기준**이라 최근 1~2개월이 누락될 수 있다. 화면에 명시한다.
5. **월세 계약은 전세가율을 내지 않는다.** 전월세 전환율을 임의로 가정하지 않는다.
6. **이 진단이 확인하지 못하는 것**(권리관계·선순위 근저당·임대인 채무)을 결과 화면에 명시한다.

| 파일 | 상태 | 책임 |

| `tests/browser.mjs` | 수정 | 단지 선택 흐름, 실패 화면 |

`rtms-client.js`를 `index.js`와 분리하는 이유는 월 범위 조회와 캐시 조합에
자체 테스트가 필요하기 때문이다. 라우트 핸들러는 얇게 유지한다.

---

## 12. 열려 있는 문제

| 문제 | 현재 판단 |
|---|---|
| `months=6`이 12회 호출을 부른다 | 캐시로 흡수. 부족하면 3개월로 줄이고 표본 부족 시 확장 |
| 단지 목록이 큰 구에서는 수백 개 | 검색어 필터 + `tradeCount` 정렬. 가상 스크롤은 하지 않는다 |
| 한 단지에 표기가 여러 개 | 가장 최근 거래의 표기를 대표로. 키는 이미 같다 |
| 캐시 테이블이 계속 커짐 | 6일짜리 행사. 방치해도 문제 없음 |
| 월세 계약 처리 | 전세가율 미표시, 전월세 분포만. 환산율 가정 안 함 |

## 13. 완료 기준
